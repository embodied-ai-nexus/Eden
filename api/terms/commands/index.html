    Command Terms¶

    Command terms produce the goal a policy is conditioned on (a base velocity, a target pose, a gait phase, a motion clip) and resample it on their own schedule. Other terms read a command by its config key through env.command_manager. The commands guide covers resampling and debug visualization; the term catalog lists every parameter.

    from eden import commands

    The base class CommandTerm is on the managers page.

    Velocity¶

    SE(2) base-velocity commands: sampled, held constant, or driven by an operator's input device.

    SE(2) velocity command terms for locomotion: sampled, held, and operator-driven.

    UniformVelocityCommand ¶

    UniformVelocityCommand(env: EnvBase, options: CommandTermOptions)

    Bases: CommandTerm

    SE(2) velocity command sampled from a uniform distribution.

    The command comprises a linear velocity in x and y direction and an angular velocity around the z-axis. It is given in the robot's base frame.

    If the heading_command attribute is set to True, the angular velocity is computed from the heading error similar to doing a proportional control on the heading error. The target heading is sampled uniformly from the provided range. Otherwise, the angular velocity is sampled uniformly from the provided range.

    ConstantVelocityCommand ¶

    ConstantVelocityCommand(env: EnvBase, options: CommandTermOptions)

    Bases: CommandTerm

    SE(2) velocity command held at a fixed value instead of resampled.

    Same command as :class:UniformVelocityCommand -- (vx, vy, wz) in the robot's base frame -- with the random generator taken out: the value is whatever :attr:command_value says, or whatever :meth:set_command was last given, and it never changes on its own.

    This is the term a deployment substitutes for the trained one. A policy deployed from its training config keeps resampling the command it was trained against, which on a robot reads as the machine wandering off on its own; holding a value the operator chose is what a deploy actually wants. It is equally the right term for an evaluation that has to hold one command for a whole episode.

    The value is clamped into lin_vel_x_range / lin_vel_y_range / ang_vel_z_range, which a deploy fills from the term it replaces, so the held command cannot leave the distribution the policy was trained on. A degenerate range — move_forward's lin_vel_x_range=(0.5, 0.5) — pins its axis: the policy only ever saw one velocity there, so that axis is not controllable and the clamp holds the single trained value whatever it is asked for. The clamp is logged.

    def build(self) -> None:

    def set_command(self, command, *, warn_on_clamp: bool = True) -> torch.Tensor:
    """Hold ``(vx, vy, wz)`` from now on, clamped into the configured ranges.

    Returns the clamped command, and warns when clamping actually bit — a value
    outside the trained ranges is worth seeing rather than silently trimming.

    Parameters
    ----------
    command
        ``(vx, vy, wz)`` in the robot's base frame.
    warn_on_clamp
        Whether to log a clamp. Off for a value nothing will hold long enough to
        matter — :class:`OperatorVelocityCommand` seeds the buffer with
        ``command_value`` only so the first observation is in range, and the device
        overwrites it on the first ``compute``.
    """
    value = torch.as_tensor(command, dtype=torch.float32, device=self.device).flatten()
    if value.numel() != 3:
        raise ValueError(f"A velocity command is (vx, vy, wz); got {value.numel()} value(s): {command}.")
    low, high = self._limits()
    clamped = torch.clamp(value, min=low, max=high)
    if warn_on_clamp and not torch.equal(clamped, value):
        # Reported from ``_limits_key``, not the fields, so the range named here is
        # always the one that was actually applied.
        vx_range, vy_range, wz_range = self._limits_key
        en.logger.warning(
            f"[commands] Velocity command {value.tolist()} is outside the trained ranges "
            f"(vx {vx_range}, vy {vy_range}, wz {wz_range}); holding {clamped.tolist()} instead."
        )
    self.vel_command_b[:] = clamped
    return clamped

    OperatorVelocityCommand ¶

    OperatorVelocityCommand(env: EnvBase, options: CommandTermOptions)

    Bases: ConstantVelocityCommand

    SE(2) velocity command driven live by a human, from a keyboard or a gamepad.

    A :class:ConstantVelocityCommand whose held value is re-read from an input device every control step. Deploy a locomotion policy with this term substituted for its trained :class:UniformVelocityCommand and the robot goes where the operator says instead of where the training distribution says.

    The device emits a normalized deflection; it is scaled into the same lin_vel_*_range / ang_vel_z_range and clamped there, so full deflection is the fastest command the policy was trained on and the operator cannot ask for more. See :mod:eden.utils.devices.se2 for the bindings.

    For deployment and interactive evaluation, not for training: it reads a physical device, so a training run would sit at whatever the sticks happen to say.

    Motion clips¶

    MotionCommand plays .npz motion clips on a plain RLEnvBase, for frozen-policy inference and single-clip tracking. Training-grade motion tracking goes through MimicRLEnvBase and the motion manager instead.

    Motion-clip command term (single- and multi-clip) and npz loaders.

    A :class:CommandTerm that drives motion-imitation / tracking policies from one or more BeyondMimic-format .npz clips. Single-clip is the M == 1 case of the multi-clip library. Shared by the frozen ONNX policy ports (sonic, twist2, humanoid_gpt, protomotionv3, beyondmimic_moves) and the beyondmimic example.

    Which motion path to use

    Eden has two motion-reference systems; pick by use case:

    • This command-term path (MotionCommand) — lightweight, for frozen-policy inference / single-clip tracking on a plain RLEnvBase. Loads npz clips verbatim and exposes the current frame (plus arbitrary future frames via :meth:MotionCommand.gather_motion_frames) directly off the command term. No dataset pipeline.
    • The manager path (eden.managers.motion_manager.MotionManager + eden.utils.motion_reference) — training-grade: dataset adapters, continuous-time interpolation, a future-frame window, symmetry augmentation, and motion-id / start-time curricula. Owned by MimicRLEnvBase and consumed by the tracking reward / observation / termination terms. See docs/guides/motion-tracking.md.

    Both expose the same world-frame vocabulary — links_*_w (tracked-link poses) and base_*_w (floating-base root) — so reward / metric code reads the same field names regardless of source.

    Config vs data vocabulary

    The configurable links_name list names the tracked links; their per-frame data is read as links_*_w. Two links_name members are special: the floating-base body (base_link_name, default links_name[0]; exposed as base_*_w, used to reset the robot root) and anchor_link_name (the yaw-warp reference, exposed as anchor_*_w). Both are resolved and validated against links_name in :meth:build. The npz on-disk keys stay body_*_w (file format); only the Python accessors are links_*.

    MultiMotionLoader(motion_files: list[str], links_idx: Tensor, device: device, links_name: list[str] | None = None)

    Batched verbatim loader for a list of BeyondMimic .npz clips.

    Mirrors :class:MotionLoader field-for-field, but stacks M clips of possibly different lengths into padded (M, T_max, ...) tensors plus a per-clip frame_total (M,). Fields are loaded VERBATIM (no interpolation, no velocity recompute) so each clip is bit-identical to the single-clip path. With M == 1 (the single-clip case) T_max == T and no padding occurs, so library[0, t] is plain single-clip indexing.

    Padding edge-replicates each clip's last valid frame (never zeros): a zero quaternion would NaN yaw_quat, and an over-read then degrades to a "hold last frame" end-of-motion behavior (the per-env wrap keeps reads in range anyway).

    if not motion_files:
        raise ValueError("MultiMotionLoader: motion_files is empty")
    self.motion_refs = [os.path.splitext(os.path.basename(f))[0] for f in motion_files]
    clips = [np.load(f) for f in motion_files]
    lengths = [int(c["joint_pos"].shape[0]) for c in clips]
    # All fields of a clip must share its frame count; otherwise the per-field
    # padding below would misalign body vs joint frames silently.
    for f, c in zip(motion_files, clips):

                raise ValueError(

                )

    # provides ``body_names``, else fall back to the Genesis idx_local in ``links_idx``.
    body_cols = [resolve_body_cols(c, links_idx, links_name) for c in clips]
    m, t_max = len(clips), max(lengths)
    self.frame_total = torch.tensor(lengths, dtype=torch.long, device=device)
    self.time_step_total = t_max  # nominal; per-clip lengths live in frame_total

    def _stack(key: str, link_sliced: bool) -> torch.Tensor:
        out: torch.Tensor | None = None
        for i, clip in enumerate(clips):
            t = torch.tensor(clip[key], dtype=torch.float32, device=device)
            if link_sliced:
                t = t[:, body_cols[i]]
            if out is None:
                out = t.new_zeros((m, t_max, *t.shape[1:]))
            length = t.shape[0]
            out[i, :length] = t
            if length < t_max:  # edge-replicate the last valid frame
                out[i, length:] = t[length - 1]
        return out

    self.dofs_vel = _stack("joint_vel", False)  # (M, T_max, 29)
    self.links_pos_w = _stack("body_pos_w", True)  # (M, T_max, n_bodies, 3)
    self.links_quat_w = _stack("body_quat_w", True)  # (M, T_max, n_bodies, 4)

    def build(self) -> None:
    self.robot = self.resolve_entity(self.entity_name)

    # NOTE: avoid tensor indexing by passing int
    robot_base_dofs_index = self.robot.find_free_base_dofs_idx_local(self.base_joint_name)
    self.robot_base_dofs_index = torch.as_tensor(
        robot_base_dofs_index, dtype=torch.long, device=self.device
    ).contiguous()
    self.base_and_dofs_index = torch.cat([self.robot_base_dofs_index, self.robot.dofs_idx_local]).contiguous()

    # Resolve a links_name member to its row in ``links_*_w``, failing loudly on a mistyped or reordered
    # name instead of a bare index error or (for the base) a silent wrong-link root reset.
    def links_index(link_name: str, field_name: str) -> int:
        if link_name not in self.links_name:
            raise ValueError(
                f"{term_subject(self)}: {field_name}={link_name!r} must be a member "
                f"of links_name; got links_name={self.links_name}"
            )
        return self.links_name.index(link_name)

    self.motion_anchor_link_index = links_index(self.anchor_link_name, "anchor_link_name")
    self.base_link_index = 0 if self.base_link_name is None else links_index(self.base_link_name, "base_link_name")

    self.links_idx = torch.tensor(
        self.robot.find_named_links_idx_local(self.links_name, preserve_order=True)[1],
        dtype=torch.long,
        device=self.device,
    )

    # Single-clip is the M=1 case of the clip library: ``motion_file`` is the
    # single-clip shorthand for ``motion_files=[motion_file]``.
    motion_files = list(self.motion_files) if self.motion_files else [self.motion_file]
    self.num_clips = len(motion_files)
    if self.num_clips > 1 and self.sampling_mode == "adaptive":
        raise ValueError(
            "adaptive sampling requires a single clip (the failure-bin curriculum partitions "
            f"one clip's timeline); got {self.num_clips} clips. Use sampling_mode 'start' or 'uniform'."
        )

    self.motion = MultiMotionLoader(motion_files, self.links_idx, device=self.device, links_name=self.links_name)
    self.time_steps = torch.zeros(self.num_envs, dtype=torch.long, device=self.device)
    self.motion_id = torch.zeros(self.num_envs, dtype=torch.long, device=self.device)
    self.frame_total = self.motion.frame_total[self.motion_id]  # (N,) per-env clip length
    self.links_pos_relative_w = torch.zeros(self.num_envs, len(self.links_name), 3, device=self.device)
    self.links_quat_relative_w = torch.zeros(self.num_envs, len(self.links_name), 4, device=self.device)
    self.links_quat_relative_w[:, :, 0].fill_(1.0)

    # Adaptive failure-bin curriculum state. The bins partition the (single)
    # clip's timeline; for multi-clip these stay allocated but unused
    # (``sampling_mode == "adaptive"`` is rejected above for M > 1).
    self.bin_count = int(self.motion.time_step_total // (1 / self._env.dt)) + 1
    self.bin_failed_count = torch.zeros(self.bin_count, dtype=torch.float, device=self.device)
    self._current_bin_failed = torch.zeros(self.bin_count, dtype=torch.float, device=self.device)
    self.bin_starts_count = torch.zeros(self.bin_count, dtype=torch.float, device=self.device)
    self._current_bin_starts = torch.zeros(self.bin_count, dtype=torch.float, device=self.device)
    self.start_bin = torch.zeros(self.num_envs, dtype=torch.long, device=self.device)
    self.kernel = torch.tensor(
        [self.adaptive_lambda**i for i in range(self.adaptive_kernel_size)],
        device=self.device,
    )
    self.kernel = self.kernel / self.kernel.sum()

    # How `_resample_command` hands the reset state to Genesis. Where its setters can keep the
    # bool env mask on the device — a `torch.where` into the state and a masked
    # forward-kinematics kernel — they take every env's row and a `range` for each DOF axis
    # (`RigidEntity.setters_take_every_row`). Otherwise, e.g. under a `dofs_name` reordered away from the
    # asset's or with hibernation on, they take the selected rows and the DOF indices: Genesis'
    # indexed path, which pays a `nonzero()` GPU->CPU sync per setter to turn the mask into indices.
    dofs_range = contiguous_range(self.base_and_dofs_index)
    qs_range = contiguous_range(self.robot.qs_idx_local)
    self._reset_through_mask = self.robot.setters_take_every_row and dofs_range is not None and qs_range is not None
    self._reset_dofs_idx = dofs_range if self._reset_through_mask else self.base_and_dofs_index
    self._reset_qs_idx = qs_range if self._reset_through_mask else self.robot.qs_idx_local

    self._init_sampling_stats()
    # Initial per-env clip assignment. Gated on M > 1 so the single-clip path
    # draws no RNG here (motion_id is already all-zeros) and its sampling
    # stream does not depend on the clip library.
    if self.num_clips > 1:
        self._sample_motions(torch.ones(self.num_envs, dtype=torch.bool, device=self.device))
    self._update_robot_state_cache()

    def post_physics_refresh(self) -> None:

    # design — they snapshot different states:
    #   1. here (post-physics, before reward) so reward/termination grade S_N, the

    # the advanced reference and the just-refreshed post-physics robot cache.
    # This is what makes reward/termination grade the temporally-aligned frame.

    def pre_physics_advance(self) -> None:
    """Advance the clip clock (+ wrap-teleport) BEFORE the physics sub-steps.

    Advance-then-grade: the reference frame is advanced before physics so the
    post-physics robot (graded at reward/termination time) is compared against
    the temporally-aligned frame — matching :class:`MotionManager`, whose clock
    advances at the start of ``MimicRLEnvBase.step``. Advancing in
    :meth:`compute` (after reward) would grade against a
    one-control-step-stale reference. Wrap-teleport runs here, before physics,
    so the teleported robot is forward-stepped and its forward kinematics stay
    fresh at reward time (no stale-FK spurious terminations).
    """
    self.time_steps += 1
    wrapped = self.time_steps >= self.frame_total  # per-env clip length
    # The bool mask `_resample_command` gets from `_resample` too, so the wrap costs no sync of
    # its own. The `.any()` gate is one: an all-False mask would write nothing, but the
    # full-batch reset draws, math and setter calls still cost ~1 ms at 4096 envs, far more
    # than the sync.
    if wrapped.any():
        self._resample_command(wrapped)
