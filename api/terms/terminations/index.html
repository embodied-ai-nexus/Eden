    Termination Terms¶

    Termination terms return a boolean per env; any true term ends the episode. A term configured with time_out=True marks a truncation rather than a failure. The rewards and terminations guide explains both; the term catalog lists every parameter.

    from eden import terminations
from eden.terms import DoneTerm

DoneTerm.configure(func=terminations.time_out, time_out=True)

    The base classes TerminationTerm and TerminationTermFuncWrapper are on the managers page.

    MetricAbove ¶

    MetricAbove(env: EnvBase, options: _TermOptionsT)

    Bases: TerminationTerm

    Terminate the envs in which the named metric's cached value is strictly above threshold.

    Reads metric_manager.get_value(metric_name): the current-step value, or — for a metric declared is_cumulative=True — the running episode sum (reset per-env on episode reset), so on a cumulative metric threshold bounds the episode total, not one step's value.

    Unlike on_metric_success this never consults the metric's success check, so it accepts a metric with contributes_to_success=False — e.g. an arm–table collision metric that must end the episode without being part of the task's success accounting.

    A missing metric manager or an unset or unknown metric_name (the error lists the active metrics) raises in :meth:build, i.e. at env construction.

    IllegalLinkContact ¶

    IllegalLinkContact(env: EnvBase, options: _TermOptionsT)

    Bases: TerminationTerm

    Terminate when any of the named links carries a net contact force above force_threshold.

    The link-level sibling of :func:illegal_contact, and the reason both exist: that term asks which entities touched, this one asks which links of one entity took load, and how hard. The knee-and-torso fall detector every locomotion task wants is this one — the entity-level term cannot express it, because a walking robot's feet are in contact with exactly the same entity (the ground or the terrain) as its knees. It mirrors Isaac Lab / mjlab's mdp.illegal_contact(body_names, threshold), minus their force history: Eden reads the net force from the most recent scene.step(), so a contact shorter than one control step can slip between two reads.

    Same reading as :class:~eden.managers.terms.rewards.common.UndesiredContacts — that term counts the offending links so a weight can price them, this one ends the episode on the first — and the two resolve links_name identically, so a config can penalise and terminate on one link set without the two drifting apart.

    PARAMETER DESCRIPTION
    entity_name

    Entity whose links are checked. Must be a rigid entity (get_links_net_contact_force).
    links_name

    :func:~eden.utils.string.resolve_matching_names-compatible patterns selecting the links that may not take load — e.g. [".*knee.*", "torso.*"]. Required: an empty list would make the term a constant False, so it raises in :meth:build listing the entity's links.
    force_threshold

    Net contact-force magnitude, in newtons, above which a link counts as illegally touching. The default of 1.0 N (Isaac Lab's) rejects numerical noise while catching any real load; raise it on a heavy robot whose links rest against each other.

def illegal_contact(env: RLEnvBase, *, entity_name: str, illegal_contact_entity_names: list[str]) -> torch.Tensor:
    entity: Entity = env.get_entity(entity_name)
    contacts = torch.zeros(env.num_envs, dtype=torch.bool, device=env.device)
    for illegal_contact_entity_name in illegal_contact_entity_names:
        illegal_contact_entity: Entity = env.get_entity(illegal_contact_entity_name)
        contacts |= entity.get_contacts(with_entity=illegal_contact_entity)["valid_mask"].any(dim=-1)
    return contacts

def dofs_pos_limit_exceeded(
    env: RLEnvBase,
    *,
    entity_name: str,
    probability: float = 1.0,
) -> torch.Tensor:
    """Terminate when any DOF position is outside the entity's soft position limits.

    ``probability`` gates the termination globally per call (one Bernoulli draw),
    leaving probabilistic slack for policies that occasionally bump the limits.
    Set to 1.0 for hard termination.
    """
    entity: Entity = env.get_entity(entity_name)
    soft = entity.soft_dofs_pos_limits
    if soft is None:
        # Non-articulated or unbuilt entity: nothing to violate.
        return torch.zeros(env.num_envs, dtype=torch.bool, device=env.device)
    dofs_pos = entity.get_dofs_pos()
    violation = torch.sum(soft_dof_pos_violation(dofs_pos, soft), dim=1) > 0.0
    return apply_probability(violation, probability)

    cumulative_reward_below_threshold ¶

    cumulative_reward_below_threshold(env: RLEnvBase, *, reward_term: str, per_step_threshold: float, grace_steps: int = 0, check_interval: int = 1) -> Tensor

    Terminate envs whose running raw reward for reward_term falls below a threshold.

    The threshold is per_step_threshold * env.dt * completed_steps.

    Mirrors dexmachina's early-reset curriculum trigger (dexmachina/envs/base_env.py:712-750). Reads the weight-free, dt-scaled accumulation via :meth:RewardManager.get_episode_sum so the threshold stays stable when reward curricula mutate term.weight at runtime.

    Mental model: average reward per completed step ≈ cum / (dt * (episode_length_buf - 1)). The term fires when that ratio drops below per_step_threshold, optionally rounded down to multiples of check_interval steps.

    PARAMETER DESCRIPTION
    env

    The environment instance.

    TYPE: RLEnvBase

    reward_term

    Name of a term registered with the reward manager. Raises KeyError (with the active term list) if missing.

    TYPE: str

    per_step_threshold

    Floor on raw per-step reward (unweighted compute() output). Compared as cum < per_step_threshold * env.dt * completed_steps. Same units as dexmachina's --early_reset_threshold flag (paper default 0.5); no manual * dt rescale at config time.

    TYPE: float

    grace_steps

    Suppress the gate while episode_length_buf <= grace_steps. Default 0 matches dexmachina (its interval=0 rung is implicitly graceful — the natural cum == 0 initial state satisfies cum < 0 vacuously).

    TYPE: int DEFAULT: 0

    check_interval

    1 (default) → continuous per-completed-step check. > 1 → dexmachina interval-ladder: round elapsed-steps down to check_interval multiples before applying the threshold. Pass 5 for early_reset_interval=5, 20 for the auxiliary imitation/contact/BC triggers.

    @TERMINATION_TERM_REGISTRY.register()
def cumulative_reward_below_threshold(
    env: RLEnvBase,
    *,
    reward_term: str,
    per_step_threshold: float,
    grace_steps: int = 0,
    check_interval: int = 1,
) -> torch.Tensor:
    """Terminate envs whose running raw reward for ``reward_term`` falls below a threshold.

    The threshold is ``per_step_threshold * env.dt * completed_steps``.

    Mirrors dexmachina's early-reset curriculum trigger
    (``dexmachina/envs/base_env.py:712-750``). Reads the weight-free,
    dt-scaled accumulation via :meth:`RewardManager.get_episode_sum` so the
    threshold stays stable when reward curricula mutate ``term.weight`` at
    runtime.

    Mental model: average reward per completed step ≈
    ``cum / (dt * (episode_length_buf - 1))``. The term fires when that
    ratio drops below ``per_step_threshold``, optionally rounded down to
    multiples of ``check_interval`` steps.

    Parameters
    ----------
    env : RLEnvBase
        The environment instance.
    reward_term : str
        Name of a term registered with the reward manager. Raises
        ``KeyError`` (with the active term list) if missing.
    per_step_threshold : float
        Floor on raw per-step reward (unweighted ``compute()`` output).
        Compared as ``cum < per_step_threshold * env.dt * completed_steps``.
        Same units as dexmachina's ``--early_reset_threshold`` flag (paper
        default ``0.5``); no manual ``* dt`` rescale at config time.
    grace_steps : int
        Suppress the gate while ``episode_length_buf <= grace_steps``.
        Default ``0`` matches dexmachina (its ``interval=0`` rung is
        implicitly graceful — the natural ``cum == 0`` initial state
        satisfies ``cum < 0`` vacuously).
    check_interval : int
        ``1`` (default) → continuous per-completed-step check.
        ``> 1`` → dexmachina interval-ladder: round elapsed-steps down
        to ``check_interval`` multiples before applying the threshold.
        Pass ``5`` for ``early_reset_interval=5``, ``20`` for the
        auxiliary imitation/contact/BC triggers.
    """
    cum = env.reward_manager.get_episode_sum(reward_term, raw=True)
    # _episode_raw_sums covers steps 1..t-1 when termination evaluates at step t,
    # so the elapsed multiplier is (episode_length_buf - 1) clamped at zero.
    completed = (env.episode_length_buf - 1).clamp(min=0)
    if check_interval > 1:
        # Match dexmachina's strict `>` rung compare: largest rung strictly below N
        # equals ((N - 1) // ci) * ci. Naive (N // ci) * ci would round one rung
        # too high on exact multiples (step 20 vs rung 20 instead of 15).
        completed = (completed // check_interval) * check_interval
    floor = per_step_threshold * env.dt * completed.float()
    return (cum < floor) & (env.episode_length_buf > grace_steps)

    joint. ``probability`` gates the termination globally per call.
    """
    entity: Entity = env.get_entity(entity_name)
    torques = entity.get_dofs_force()
    limit = entity.default_dofs_force_limits
    if limit is None:
        return torch.zeros(env.num_envs, dtype=torch.bool, device=env.device)
    # default_dofs_force_limits is shaped (num_envs, num_dofs) when batched, else (1, num_dofs).
    threshold = soft_ratio * limit
    violation = (torques.abs() > threshold).any(dim=1)
    return apply_probability(violation, probability)

    Motion tracking¶

    Termination terms that gate episodes on robot-vs-motion-ref tracking error.

    Two families:

    • Direct world-frame gates (function-style, registry keys motion_{base,link,dofs}_*_tracking_error_above): hard > threshold tests on raw distances. Symmetric with :mod:eden.managers.terms.rewards.tracking. The dexmachina ManipTrans curriculum kills envs whose pos / rot / per-link error exceed an eps; these terms supply the gates (decaying the eps is a curriculum's job).
    • Anchor-yaw-warped gates (bad_anchor_*, BadMotionLinkPosZOnly): compare robot state against the yaw-warped motion target so the gate doesn't fire just because the robot drifted in heading.

    Also exposes :func:motion_ends, which fires when the motion buffer for the entity runs out of frames.

    Reduction conventions for multi-link / multi-DOF terms:

    • "max" (default) — strict per-element gate; any link/DOF beyond threshold triggers. Matches ManipTrans semantics.
    • "mean" — averaged-error gate; lenient.
