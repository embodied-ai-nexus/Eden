    Grasp Sampling¶

    Grasp samplers propose 6-DoF grasps of an object in a built env, from a camera's point cloud or the object's own cloud, for a given end effector. A sampler is a GraspSamplerBase subclass registered in GRASP_SAMPLER_REGISTRY and returns a GraspResult. Two backends ship: GraspGen (one model per gripper) and GraspGenX (one cross-embodiment model, the gripper selected by name). The grasp sampling guide covers installation and use.

    from eden.extensions.grasp_sampling.base import GRASP_SAMPLER_REGISTRY, GraspResult, GraspSamplerBase
from eden.options.extensions.grasp_sampling import GraspSamplerOptions

    Base class, result and registry¶

    Base class and result type for grasp samplers.

    A grasp sampler turns one entity's point cloud into 6-DoF grasp poses. :class:GraspSamplerBase owns everything that is the same for every backend — reading the target's points off the camera or its surface, the obstacle cloud for collision filtering, ranking, the frame the poses place, and packing the result into Eden's pos / wxyz quat tensors — so a backend only implements :meth:~GraspSamplerBase._infer (the model call), declares its pose frame, and, if its grippers carry collision geometry, implements :meth:~GraspSamplerBase._collision_free.

    Frames. Every backend's model returns grasp frames: z is the approach direction and x the direction the fingers close along, whatever the gripper. A grasp frame is generally no link of the real gripper. Each backend therefore names the frame its poses place instead (GraspGenX: its gripper description's base link), and with end_effector= an Eden robot's link, from the pairings it has verified (:attr:GraspSamplerBase.END_EFFECTORS).

    One call samples for one env (sample_grasps(..., env_idx=)), or for several with one render and one batched model call (:meth:GraspSamplerBase.sample_grasps_batch). In a batched env the camera must render each env on its own (EnvOptions(env_separate_rigid=True) or the batch renderer): a shared view holds every env's copy of the target under one segmentation id.

    @classmethod
def from_transforms(
    cls,
    transforms: np.ndarray,
    confidences: np.ndarray,
    device: torch.device,
    max_grasps: int | None = None,
) -> GraspResult:
    """Rank ``(n, 4, 4)`` world-frame ``transforms`` by confidence and convert them to pos/quat."""
    order = np.argsort(-confidences, kind="stable")[:max_grasps]
    transforms = torch.as_tensor(transforms[order], dtype=gs.tc_float, device=device).reshape(-1, 4, 4)
    pos, quat = T_to_trans_quat(transforms)
    return cls(
        pos=pos, quat=quat, confidences=torch.as_tensor(confidences[order], dtype=gs.tc_float, device=device)
    )

    pose_link_name property ¶
    pose_link_name: str | None

    The link each returned pose places: end_effector's link when set, else the backend's own.

    None when the poses are the backend's grasp frame itself, which is no link of the gripper (GraspGen without end_effector).

    approach_axis property ¶
    approach_axis: Tensor

    The approach direction, a unit vector of shape (3,) in the posed link's frame, on the env's device.

    A grasp moves the gripper along this axis onto the object, so a pregrasp backs off along it: pos - transform_by_quat(approach_axis[None], quat) * distance.

    closing_axis property ¶
    closing_axis: Tensor

    The direction the fingers close along, a unit vector of shape (3,) in the posed link's frame.

    With :attr:approach_axis and :attr:tcp_offset it is what a scripted demonstrator's top-down move_to(pos, yaw) needs from a grasp: the heading of transform_by_quat(closing_axis[None], quat) is the one its fingers must close along.

    tcp_offset property ¶
    tcp_offset: Tensor

    The TCP in the posed link's frame, shape (3,), on the env's device.

    The TCP is the point the grasp puts on the object (for a parallel jaw, the fingertip center), so pos + transform_by_quat(tcp_offset[None], quat) is where a grasp puts it.

    def sample_grasps_batch(self, entity_name: str, envs_idx: Sequence[int] | None = None) -> list[GraspResult]:
    """Sample grasps of entity ``entity_name`` in several envs at once.

    The camera renders once for all of them and the model runs once on all their clouds, where
    :meth:`sample_grasps` per env would render the whole batch and run the model for each. A
    scripted demonstrator that runs one routine per env samples every env here first and hands
    each routine its result.

    Parameters
    ----------
    entity_name : str
        The entity to grasp.
    envs_idx : Sequence[int] | None
        The envs to sample in; ``None`` samples every env.

    Returns
    -------
    list[GraspResult]
        One result per entry of ``envs_idx``, in its order; each as :meth:`sample_grasps` returns it.
    """
    entity = resolve_named_entity(
        self.env.entities, entity_name, hint="sample_grasps(entity_name=...) names the entity to grasp."
    )
    envs_idx = list(range(self.env.num_envs)) if envs_idx is None else [int(i) for i in envs_idx]
    for env_idx in envs_idx:
        if not 0 <= env_idx < self.env.num_envs:
            raise IndexError(f"env_idx={env_idx} is out of range for this env's num_envs={self.env.num_envs}.")
    grasp_T_pose = self._pose_frame()
    clouds = self._read_clouds(entity_name, entity, envs_idx)

    outputs = self._infer_batch([object_points for object_points, _ in clouds])
    if len(outputs) != len(clouds):
        raise RuntimeError(
            f"{type(self).__name__}._infer_batch returned {len(outputs)} results for {len(clouds)} clouds; it "
            f"must return one (transforms, confidences) pair per cloud, in order."
        )
    return [
        self._finish(grasps, confidences, scene_points, grasp_T_pose)
        for (grasps, confidences), (_, scene_points) in zip(outputs, clouds)
    ]

    Options¶

    Configuration options for grasp-sampling extensions.

    :class:GraspSamplerOptions mirrors :class:~eden.extensions.grasp_sampling.base.GraspSamplerBase's attributes, so the fields every backend shares are type-checked at configure() time. Backend-specific knobs stay as class attributes on the backend and arrive as extras — e.g. GraspGen's gripper_config or GraspGenX's gripper_name / planner.

    :class:GraspMoEOptions groups GraspGenX's GraspMoE planner knobs so they validate as a unit (extra="forbid" plus Literal choices) instead of reaching the planner unchecked.

    GraspSamplerOptions ¶

    GraspSamplerOptions(**data)

    Bases: DynamicConfigurableOptions

    Options shared by every grasp-sampling backend.

    PARAMETER DESCRIPTION
    camera_name

    Camera whose point cloud the sampler reads: the target's visible points when object_cloud="camera", and the obstacle cloud filter_collisions checks against. It must use the legacy camera backend (no sensor_options), the one that renders point clouds and segmentation. Not needed when neither of those reads it.

    TYPE: str

    object_cloud

    Where the target's points come from. "camera" takes the pixels the camera sees of it, which is what a real robot has. "surface" samples the entity's whole surface, hidden underside included, so the model also proposes grasps from below whatever it rests on.

    GraspGenX¶

    Eden wrapper around GraspGenX: cross-embodiment 6-DoF grasp generation.

    GraspGenX (NVlabs/GraspGenX <https://github.com/NVlabs/GraspGenX>) conditions one diffusion model, and its discriminator, on a gripper description: the gripper's swept volume, its open and closed point clouds, and its URDF. A gripper is therefore picked by name, with no per-gripper model. Eden consumes the inference-only fork Kashu7100/GraspGenX <https://github.com/Kashu7100/GraspGenX>, published as eden-graspgenx (import name graspgenx) and installed by the graspgenx extra. The checkpoints and the gripper descriptions download from Hugging Face on first use. See docs/guides/grasp-sampling.md.

    Frames. GraspGenX poses a grasp at the world link of the description's URDF: its z axis is the approach direction and its x axis the closing direction, whatever the gripper. That frame is no link of the real gripper; the description welds the gripper's base link to it through a fixed world_joint (rotated 90° about z for the Franka hand and the Robotiq 2F-85, offset by several centimeters for the dexterous hands). The sampler applies that joint, so each pose it returns is the pose of the description's base link (pose_link_name) — or, with end_effector=, of the Eden robot's link it pairs that base link with (:attr:GraspGenXSampler.END_EFFECTORS).

            "GraspGenXSampler needs gripper_name=, the GraspGenX gripper description to sample for, e.g. "

            "GraspGenX runs on CUDA only, and torch sees no CUDA device. Fix: run on a machine with an NVIDIA "
            "GPU (select one with CUDA_VISIBLE_DEVICES); the Eden env itself may stay on gs.cpu."

    base_link_name, grasp_T_base = _root_joint(self._description_dir / "gripper.urdf")
    with open(self._description_dir / "config.json") as f:

    missing = [key for key in ("open", "close", "fingertip") if key not in config]
    if missing:
        raise ValueError(
            f"Gripper description '{self._description_dir}' has no {missing} configuration in its config.json, "
            f"which every GraspGenX description declares; check $GRASPGENX_GRIPPER_CFG_DIR if it points at a "
            f"custom one."

    self._set_pose_frame(base_link_name, grasp_T_base, np.asarray(config["fingertip"], dtype=np.float64))

    self._close_dofs_pos = {name: float(value) for name, value in config["close"].items()}

    checkpoint_dir = self._resolve_checkpoint_dir(graspgenx)
    en.logger.info(f"GraspGenX: loading '{self.gripper_name}' with the checkpoints under {checkpoint_dir}")

    GraspGen¶

    Eden wrapper around GraspGen: diffusion-based 6-DoF grasp generation, one model per gripper.

    GraspGen (NVlabs/GraspGen <https://github.com/NVlabs/GraspGen>_) is consumed through the packaged eden-grasp-gen (import name grasp_gen), installed by the graspgen extra; grasp_gen download fetches its per-gripper models into $GRASPGEN_CHECKPOINT_DIR. For a gripper GraspGen has no model of, use :class:~eden.extensions.grasp_sampling.graspgenx.GraspGenXSampler, whose single model takes the gripper by name.

    Frames. A GraspGen pose is its grasp frame (z approach, x closing), with its origin at the gripper's base. That is no link of an Eden robot: the Franka's hand link closes its fingers along y, so it is the grasp frame turned 90° about z, and a hand driven onto the bare grasp frame closes across the wrong axis. Configure end_effector= (:attr:GraspGenSampler.END_EFFECTORS) for poses of the Eden link instead.
