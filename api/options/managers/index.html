    Manager Options¶

    Each manager has a *ManagerOptions container and a *TermOptions class for one of its terms. You rarely build a term options object by hand: <Term>.configure(...) returns one. The container holds terms as named fields, and the name is the key other code uses (env.reward_manager, get_term("<name>"), a reward's command_name, ...). Observation and reward terms are grouped one level further (ObservationGroupOptions, RewardGroupOptions). The terms guide explains configuring terms.

    from eden.options.managers.observations import ObservationGroupOptions, ObservationManagerOptions
from eden.options.managers.rewards import RewardManagerOptions

    Base¶

    ManagerTermOptions is the base of every term's options; FunctionTermOptions adds the params dict that configure(func=...) fills, for the kinds that accept function terms. ManagerOptions is the base of the containers.

    Base manager-options class with dynamic per-term fields.

    ManagerTermOptions ¶

    ManagerTermOptions(**data)

    Bases: DynamicConfigurableOptions

    Base for all per-term options (RewardTermOptions, EventTermOptions, ...).

    Term options stay extra="allow" because class-based terms carry their per-term parameters as extras (the options class is shared by every term of the kind). Typo protection comes from validating those extras against the registered term instead:

    • At construction and on attribute assignment (model_post_init / __setattr__): when name resolves in the kind's term registry — stamped onto this class as _term_registry_ by TermRegistry.__init__ — extras must be parameters of the registered term, and for function terms the params keys must be arguments of the registered function. RewardTermOptions(name="upright", wieght=2.0) and options.wieght = 2.0 both raise in the config file that contains the typo (a rejected assignment is rolled back).
    • On copy-with-changes (updated(...) / model_copy(update=...)): the same check runs on the copy — pydantic's update= is otherwise unvalidated and would park {"wieght": 2.0} as an extra next to the untouched weight.
    • At build (ConfigurableMixin.__init__): the pre-existing invalid-parameter check backstops options whose name was missing or not yet registered at construction time.

    ManagerOptions ¶

    ManagerOptions(**data)

    Bases: DynamicConfigurableOptions, Generic[T_TermOptions]

    Generic base class for manager options.

    Stores term options as extra fields, validates their types via model_post_init, and provides disable_term for runtime removal.

    Usage::

    class EventManagerOptions(ManagerOptions[EventTermOptions]):
    pass

# Entries forming a union parametrize with `|` — accepted types stay visible
# in the class signature (e.g. reward managers accept flat terms or groups):
class RewardManagerOptions(ManagerOptions[RewardTermOptions | RewardGroupOptions]):
    pass

    The term options class (or union) is automatically extracted from the generic parameter; isinstance accepts union types directly.

    def term_keys(self) -> tuple[str, ...]:
    """Return only the registered ``ManagerTerm`` entry names.

    These are the extras validated by :meth:`model_post_init` to be
    ``_term_options_class_`` instances.

    This is intentionally distinct from :meth:`ConfigurableOptions.keys`,
    which returns every named child of the options object — including
    declared model fields that are config knobs (e.g.
    ``RecorderManagerOptions.dataset_filename``), not terms.
    """
    extra = self.__pydantic_extra__ or {}
    return tuple(key for key in extra if not key.startswith("_option_"))

    ObservationTermOptions ¶

    ObservationTermOptions(**data)

    Bases: FunctionTermOptions

    Observation term specification.

    The manager processes each frame of the term's output in this order: modifiers, noise, clip, scale, then the group's nan_policy, and last the history window.

    PARAMETER DESCRIPTION
    modifiers

    Transforms applied to the term's output in list order, before noise (default=[], none). Each entry is a registered :class:~eden.managers.modifiers.base.ObservationModifier configured with <ModifierClass>.configure(...), e.g. ExponentialMovingAverage.configure(alpha=0.2) or ObservationDelay.configure(control_steps=2). Unlike noise, modifiers run in every mode: training, eval and deployment. A modifier must return the shape, dtype and device it receives.
    noise

    Noise model applied to the observation, in training only (default=None, no noise).
    clip

    Range to clip the observation values (default=None, no clipping).
    scale

    Scaling factor applied to the observation (default=1.0). A list gives a per-component scale matched against the term's feature dim — the last dimension of its raw compute() output — validated at env-construction time and applied before history stacking.
    history_length

    Number of previous observations to include (default=0, no history).
    flatten_history_dim

    Whether to flatten the history into the feature axis, giving (num_envs, history_length * dim) instead of (num_envs, history_length, dim) (default=True, the same as the group's).
    backfill

    Whether to backfill the history with the first observation (default=True). If False, the history will be filled with zeros.

    def disable_term(self, name: str) -> None:
    """Remove a flat term, a whole group, or a term nested inside exactly one group, by name.

    The name must resolve unambiguously. If it matches more than one entry (a term
    declared in several groups, or a top-level entry and a nested term), this raises
    ``ValueError`` — disable through the owning group instead:
    ``getattr(options, group).disable_term(name)``. Ambiguity here is name-based, not
    activity-based: a weight-0 (inert) duplicate still counts as a match, unlike the
    manager's build-time uniqueness check, because options can't know final weights.
    """
    owner_groups = self._groups_containing(name)
    places = (["top level"] if name in self.term_keys() else []) + [f"group '{g}'" for g in owner_groups]
    if len(places) > 1:
        raise ValueError(
            f"Name '{name}' is ambiguous ({' and '.join(places)}). To remove a nested term, call "
            f"disable_term on its group: getattr(options, group).disable_term({name!r})."
        )
    if owner_groups:
        getattr(self, owner_groups[0]).disable_term(name)
        return
    # Top-level hit (flat term or whole group), or the canonical KeyError.
    self._remove_named_child(name, noun="term")

"concat_motion_bins" draws one motion_bin_length_s bin from all motions' bins concatenated (so a longer motion is proportionally likelier) and starts inside it; requires motion_bin_length_s.

    (min, max) fractions of the clip duration the start time is drawn uniformly from. Used only when max > 0 and motion_bin_length_s is None (bin sampling takes priority). Defaults to (0.0, 0.0): every clip starts at its first frame.

    adaptive_sampling

    Master toggle for adaptive start-time (intra-motion bin) sampling. Defaults to False.
    adaptive_kernel_size

    Temporal smoothing kernel width K. Smooths each failure onto the bin it died in and the K - 1 bins before it, so starts move onto the run-up to a hard moment (BeyondMimic's look-ahead kernel). 1 disables smoothing. Defaults to 1.
    adaptive_lambda

    Exponential decay for kernel weights: the death bin weighs 1, the bin i before it adaptive_lambda ** i, normalised to sum to 1. Defaults to 0.8.
    adaptive_uniform_ratio

    Minimum uniform floor in sampling probabilities. Defaults to 0.1.
    adaptive_alpha

    EMA blend rate for failure counts. Defaults to 0.001.
    adaptive_failure_rate_max_over_mean

    Per-START-bin concentration clamp for adaptive start-time sampling. A bin whose (smoothed) failure rate exceeds mean * this (per-motion mean over its bins) is clipped to that ceiling before normalization, so no single bin can absorb arbitrarily much probability mass even if its failure rate is pathologically high (e.g. a momentarily impossible frame). Bin-level analogue of motion_weight_failure_rate_max_over_mean; without it the uniform mix alone only bounds the floor, not the peak, so the start distribution can still collapse onto one bin. <= 0 disables the clamp. Defaults to 10.0.
    motion_weights

    Initial per-motion-id sampling weights, one entry per loaded trajectory in motion-id order. None (default) weights every motion equally. A list[float] supplies the weights inline; a str is a path to a text/JSON file (loaded via load_text) holding a "motion_weights" key with that list — convenient for large clip libraries. The length must equal the number of loaded trajectories or build raises. When adaptive_motion_weights is True these are the starting weights the curriculum then rewrites.
    adaptive_motion_weights

    Master toggle for adaptive per-motion-id sampling (hard-motion mining). Orthogonal to adaptive_sampling (which controls intra-motion start-time bins). When True, _motion_weights is updated each training iteration based on per-motion success / early-termination outcomes during rollouts. Defaults to False.
    motion_weight_success_discount

    Per-success multiplicative decay applied to a motion's weight when its motion plays to its natural end (regardless of whether the env also terminated this step). < 1.0 shrinks the weight of easy motions; = 1.0 disables decay. Defaults to 0.999 (matches ProtoMotions reference).
    motion_weight_failure_amplify

    Per-failure multiplicative gain applied to a motion's weight when an episode terminates early without the motion completing. > 1.0 boosts the weight of hard motions; = 1.0 disables amplification. Defaults to 2.0 (matches ProtoMotions reference). For a gentler, symmetric per-iter pressure, set this to a value just above 1 (e.g. 1.001) alongside motion_weight_success_discount=0.999.
    motion_weight_floor

    Lower clamp on per-motion weight (before re-normalization), so no motion can be permanently zeroed out. Defaults to 1e-3. Only consulted by motion_weight_update_mode="compound"; the snapshot mode bounds weights via motion_weight_failure_rate_max_over_mean + motion_weight_uniform_mix instead.
    motion_weight_update_mode

    How _motion_weights is rewritten from the drained outcome counts:

    • "snapshot" (default): stateless rate-proportional formulation ported from SONIC's update_adaptive_sampling_probabilities (motion_lib_base.py:2570-2585). Computes failure_rate = n_failure / (n_success + n_failure), clamps outliers at mean_failure_rate * failure_rate_max_over_mean, normalises, then blends with uniform via uniform_mix. The result is always the same function of the current drained counts — no history compounds. success_discount / failure_amplify / floor are ignored under this mode.
    • "compound" (opt-in): log-space additive update log_w += n_success * log(success_discount) + n_failure * log(failure_amplify). Integrates all historical outcomes forever; any persistent failure-rate bias compounds exponentially until a motion saturates at the floor or at 1.0. Observed to collapse to a single motion at LAFAN1 scale; kept only for ablation runs.
    motion_weight_uniform_mix

    Applied AFTER the curriculum update under either mode: w := (1 - α) * w + α / N. Caps maximum concentration at (1 - α) + α/N and floors minimum at α/N, independent of the update mode's own dynamics. Defaults to 0.0 (off).
    motion_weight_failure_rate_max_over_mean

    Snapshot-mode-only outlier clamp. A motion with failure rate greater than mean * this is clipped to that ceiling before being converted to a probability. With N=12 and clamp=200, the worst case is one motion captures up to ~95% of the pre-mix probability mass; combined with uniform_mix=0.1 the worst-case cap becomes ~85%. Defaults to 200.0 (matches SONIC's adp_samp_failure_rate_max_over_mean).
    motion_weight_update_every_n_iters

    Apply the curriculum update every N PPO iterations. Outcomes accumulate in between. Defaults to 1.
    log_per_motion_metrics

    Emit per-motion-id distributions as wandb.Histogram panels under MotionPerMotion/Weights (current sampling weights) and MotionPerMotion/Outcome/{success_count, failure_count, total, success_rate} (per-drain counts). One histogram per metric per iter — independent of motion count.
